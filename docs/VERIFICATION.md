## Разговор после отдельного запуска — 16 сентября 2026

Отдельный запуск без вопроса теперь оставляет навык открытым для уточнений. Запуск сразу с вопросом сохраняет автовыход после полного ответа. Режим разговора хранится только в сессии и не записывается в личные настройки при выборе группы. Явное предпочтение выхода имеет приоритет. «Спасибо», «всё», «всё, спасибо» и «спасибо, всё» завершают разговор; благодарность вместе с вопросом его не прерывает.

Прошли 142 теста диалога, ответов, состояний и адресатов. После добавления выхода по благодарности прошёл набор из 130 тестов языка, уточнений и разговорных запросов; наборы пересекаются. Проверены первый выбор группы, гостевой и авторизованный пользователь, сохранение дня и номера пары, новый запуск со старым состоянием, явные настройки выхода, отключение нового поведения в конфигурации и сбой источника. Lint, форматирование и валидация данных прошли; новых зависимостей нет.

После развёртывания каждый из двух ID навыка прошёл восемь HTTPS-запросов: отдельный запуск → завтра → предметы → вторая пара → спасибо; новый запрос одной фразой; отдельный запуск с принудительным автовыходом → завтра. Ответы совпали между версиями, предметы сверены с API для нужной даты. Проверки использовали отдельные синтетические состояния и не записывали пользовательские настройки.

В чате опубликованной приватной версии отдельно проверено: запуск → «завтра» → «какие предметы завтра» → «спасибо». День сохранился, после двух ответов сессия оставалась открытой, после благодарности консоль показала её завершение. Личные настройки не менялись. На физической Станции новый порядок завершения пока не проверен.

Контейнер healthy, перезапусков нет, `/readyz` — ready. Файлы на сервере совпадают с локальными; проверенные файлы бота и virtual host не изменены. Сохранены образ `alisa-schedule:before-launch-modes-20260916` и архив `/opt/alisa-schedule/before-launch-modes-20260916.tar.gz`. При откате восстановить код и `data/responses.json` вместе.

В опубликованных настройках приватной версии подтверждено имя «Кэпик тест». Сообщение Станции «такого навыка нет» этим изменением не исправлено: backend не управляет распознаванием активационной команды. Проверка в консоли Яндекса не заменяет голосовой запуск на Станции.

## Уточнение предметов — 16 сентября 2026

Добавлены запросы конкретного номера пары и разовые уточнения предметов. «Предметы» больше не меняет постоянный режим; для этого остаётся «называй предметы». В открытом разговоре уточнение сохраняет день и группу или преподавателя. После первой пары или конкретного номера короткое уточнение относится к этой паре. После выхода требуется новый запуск с нужным днём.

После сборки и развёртывания оба ID навыка прошли HTTPS-проверку на реальном расписании: предметы всего дня, предмет конкретной пары, уточнение в открытом разговоре и предметы преподавателя. Проверочные запросы использовали отдельные тестовые состояния: настройки владельца в хранилище Яндекса не сбрасывались и не менялись. Полные ответы закрывали сессию при включённом автовыходе. ## Реальные запросы

- Через HTTPS проверены выбор группы, завтра, первая пара и количество.
- На расписании 16 сентября проверены группы первого, второго, третьего и четвёртого курсов. Первый курс получает предметы, старшие — фамилии. Поля преподавателей в проверенных данных содержат фамилию и инициалы; инициалы удаляются.
- После отключения даты ответы для `141-Д9-1КСК` и `103-Д9-3ИНС` занимают 41 и 56 символов. День сохраняется в состоянии диалога, но не проговаривается.
- В тестовом чате Яндекса команда «называй предметы» изменила ответ; выбор сохранился после «выход» и нового обращения. После теста возвращён режим по курсу.
- Яндекс преобразует «какая первая пара» в «какая 1 пара». Этот вариант проверен в чате и отдельным тестом.
- В каталоге источника 65 доступных групп после исключения ошибочной `103-Д3-3ИНС` только в навыке.
- Существующие `/` и `/api/docs/` отвечают HTTP 200. Контрольные суммы virtual host, `api.py` и `schedules/group_schedule.py` бота совпадают с исходными.

При первоначальном развёртывании проверен тёплый кэш: 64 успешных запроса, concurrency 8, медиана 236,4 мс, p95 297,7 мс. Измерение выполнено из контейнера с лимитом 0,5 CPU и 192 MiB памяти; внешний TLS и холодные запросы к источнику в него не входят. При обновлении только текстов этот замер не повторялся.
