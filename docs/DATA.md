# Данные и адаптер источника

## API ККЭПика

Используются четыре публичных маршрута:

```http
GET https://kkepik.rub1kub.ru/api/teachers
GET https://kkepik.rub1kub.ru/api/schedule/teacher?teacher=<точное имя из каталога>&date=16.09.2026
GET https://kkepik.rub1kub.ru/api/groups
GET https://kkepik.rub1kub.ru/api/schedule/group?group=103-Д9-3ИНС&date=16.09.2026
```

API возвращает строки вида `▪️2 пара – Математика – 22`. Адаптер превращает их в типизированные занятия. Извлеченные дата и группа обязаны совпасть с запросом. Неизвестный формат считается ошибкой источника; строки нельзя молча пропускать и ошибочно уменьшать количество пар.

Ограничения текущего API:

- `404` объединяет отсутствие публикации и отсутствие группы в конкретной публикации. Ответ: «На этот день нет опубликованного расписания группы». Это отличается от ответа «пар нет».
- `200` с пустыми парами означает отсутствие занятий; `Нет` и отмененные пары не считаются.
- Несколько строк одного номера сохраняются как варианты. API не дает точного соответствия подгруппам — навык не присваивает им выдуманные номера подгрупп.
- У API нет структурированной метки «замена»: новая публикация на ту же дату становится доступна после истечения кэша. Нельзя достоверно сообщить, что именно изменилось, без истории версий источника.
- Текстовое разделение предмета, преподавателя и аудитории находится только в адаптере. Нет копии PDF-парсера и общей БД с ботом. При изменении формата нужно обновить адаптер и его контрактные тесты.

## Внутренний объект дня

```json
{
  "group_id": "103-Д9-3ИНС",
  "date": "2026-09-16",
  "lessons": [
    {
      "number": 2,
      "subject": "Компьютерные сети",
      "teacher": "",
      "room": "22",
      "subgroup": "",
      "start": "10:25",
      "end": "11:45"
    }
  ],
  "note": ""
}
```

| Поле | Правило |
| --- | --- |
| `group_id` | Стабильный ID из каталога, для ККЭПика — полное обозначение группы |
| `date` | ISO-дата конкретной публикации |
| `lessons` | Массив занятий; `[]` означает, что занятий нет |
| `number` | Целый номер пары 1–12; может повторяться только с разными `subgroup` |
| `subject` | Обязательный предмет, максимум 200 символов |
| `teacher`, `room`, `subgroup` | Необязательные строки; пустая строка означает отсутствие сведений |
| `start`, `end` | Оба значения `ЧЧ:ММ` или оба отсутствуют; начало раньше конца |
| `note` | Примечание ко всему дню, максимум 200 символов |

Результат провайдера дополняется `source` (`kkepik`, `file`, `override`), временем получения `fetched_at`, признаком сохраненной версии `stale` и признаком демонстрации `demo`. Диалог получает этот объект; разбор строк API остаётся в адаптере.

## Расписание преподавателя

`teachers()` возвращает `id`, `name`, `aliases`. ID — точное значение из API, включая инициалы. Оно используется для чтения источника и не озвучивается. `teacher_day(id, date)` возвращает `teacher_id`, `date`, `lessons`, `source`, `fetched_at`, `stale`, `demo`, `partial`.

Занятие преподавателя содержит `number`, список `groups`, необязательные `subject`, `subgroup`, `start`, `end`. В источнике встречаются строки `▪️2 пара – 103-Д9-3ИНС – Сети – ауд. 22` и строки без предмета. Адаптер проверяет дату и преподавателя, удаляет аудитории и сохраняет все группы. Неизвестный формат вызывает ошибку, а не пустое расписание.

Каталог преподавателей и его расписания используют тот же лимит запросов, объединение обращений и сроки кэша, что и группы. Запрос одного преподавателя не порождает запросы по всем группам.

Распознаются точные имена из каталога, фамилии и регулярные падежные формы. Для нестандартного склонения, полного имени или варианта распознавания добавьте `teacher_aliases` в `data/college.json`. Пример с вымышленным преподавателем:

```json
"teacher_aliases": {"Тестов А. Б.": ["Алексей Борисович Тестов"]}
```

Однозначное совпадение выбирается сразу; однофамильцы требуют уточнения. При одинаковой фамилии и одинаковых инициалах сам API не различает людей — навык также не сможет их разделить без разных ID у источника.

В файловом источнике преподаватели собираются из поля `teacher` занятий; нескольких разделяйте `;`. `partial: true` означает, что на дату представлены не все группы. Даже отсутствие занятий в таком результате сопровождается оговоркой о неполноте.

## Собственные замены

`data/overrides.json`:

```json
{
  "schema_version": 1,
  "replacements": [
    {
      "group_id": "103-Д9-3ИНС",
      "date": "2026-09-16",
      "note": "Изменено расписание",
      "lessons": [
        {"number": 2, "subject": "Компьютерные сети", "room": "35", "start": "10:25", "end": "11:45"}
      ]
    },
    {
      "group_id": "103-Д9-3ИНС",
      "date": "2026-09-18",
      "note": "Занятия отменены",
      "lessons": []
    }
  ]
}
```

Каждая запись **полностью заменяет день**. При изменении одной пары нужно перечислить и остальные актуальные пары. Это дает однозначные отмены, переносы и добавления без зависимости от прежней версии источника. Дубликаты пары `group_id/date`, неизвестные поля, повторные JSON-ключи и некорректное время отклоняются.

Замены учитываются в расписании преподавателя: занятия заменённых групп удаляются из ответа источника, затем добавляются актуальные занятия из замен. Для сопоставления заполните `teacher` точным именем из каталога. Если источника за день нет, а есть только занятия из замен, результат помечается `partial`, и Алиса предупреждает о неполноте.

Для публикации подготовьте отдельный файл и выполните из каталога проекта:

```bash
.venv/bin/python -m scripts.publish_overrides data/overrides.local.json
```

Файл сначала валидируется, затем заменяется атомарно. Сервис подхватывает изменения при следующем запросе. Некорректно отредактированный активный файл вызывает сообщение о недоступности; предыдущие занятия не выдаются как якобы актуальные. Для возврата к API удалите нужную запись через такую же публикацию файла.

## Полностью автономный источник

`SCHEDULE_PROVIDER=file` использует `data/schedule.example.json`. Корневые поля: `schema_version`, `demo`, `groups` и `days`. Группы содержат `id`, `name`, `aliases`. Дни имеют формат выше; отсутствующий день означает отсутствие данных, а не выходной. ID каждого дня должен существовать в каталоге.

Демонстрационный файл содержит вымышленные предметы и даты. Для реальной автономной эксплуатации создайте собственный файл, задайте `SCHEDULE_FILE` и `demo: false`. Чередование недель нужно заранее развернуть в расписание по датам.

## Конфигурация колледжа

`college.json` хранит название ККЭП, `timezone`, таблицы `bells.weekday` и `bells.saturday`, словари `group_aliases` и `subject_aliases`, а также `excluded_groups` и `group_courses`. Курс обычно берётся из цифры после последнего дефиса; `group_courses` задаёт исключения. Этот файл читается при старте; после его изменения перезапустите только сервис навыка. В нем нет пользовательских данных или ключей доступа.
