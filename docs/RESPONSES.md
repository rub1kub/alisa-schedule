# Ответы Алисы

Все реплики и подписи кнопок лежат в `data/responses.json`. Логика диалога выбирает шаблон и подставляет данные. Кабинеты остаются в модели расписания, но в ответ не попадают.

## Что слышит студент

При первом обращении: «Какая группа? Можно короткий номер». Выбор подтверждается один раз. Вопрос определяет день; Алиса не повторяет дату и группу перед каждой выдачей.

По умолчанию первый курс слышит предметы, второй–четвёртый — фамилии. Курс берётся после последнего дефиса в обозначении группы. Для нестандартного кода задайте курс явно в `college.json`:

```json
"group_courses": {"103-Д9-3ИНС": 3}
```

Инициалы из поля преподавателя удаляются. Если преподаватель не указан, звучит предмет. Предупреждения о сохранённой копии, примере расписания, замене и примечания к дню сохраняются при любом режиме.

| Команда | Результат |
| --- | --- |
| «Называй предметы» | Сохранить режим предметов |
| «Называй преподавателей» или «называй фамилии» | Сохранить режим фамилий |
| «Предметы и преподаватели» | Называть оба поля |
| «Выбирай по курсу» | Вернуться к правилу курса |
| «Какие предметы завтра?» | Предметы только в этом ответе |
| «Кто ведёт первую пару?» | Фамилия для первой пары |

Постоянный выбор сохраняется вместе с группой в хранилище Яндекса. «Забудь группу» очищает группу, сохраняя формат ответа. Гостевое приложение и авторизованный пользователь имеют отдельные настройки.

## Настройки владельца

Поле `options`:

| Ключ | По умолчанию | Значение |
| --- | --- | --- |
| `lesson_label` | `auto` | `auto`, `subject`, `teacher` или `both` |
| `course_labels` | `1: subject`, `2–4: teacher` | Режим для каждого курса |
| `show_group` | `false` | Повторять группу перед расписанием |
| `schedule_time` | `none` | `none`, `start` или `range` для расписания дня |
| `first_time` | `start` | Время первой фактической пары: `none`, `start` или `range` |
| `date_format` | `none` | `none`: без даты; `short`: «16 сентября»; `full`: с годом и днём недели |
| `page_chars` | `700` | Длина части ответа, 300–1024 символа |

Приоритет формата: конкретный вопрос → сохранённый выбор студента → настройка владельца → правило курса. При неизвестном курсе или отсутствии правила используются предметы.

В `texts` можно менять формулировки. Например:

```json
"welcome": "Сегодня или завтра?",
"day_count": "{count}.",
"lesson": "{number}-я — {label}"
```

`label` уже содержит предмет, фамилию или оба поля. Список ключей и разрешённых подстановок задан в `app/responses.py`. Ключи и подстановки нужно сохранять. Обращения к атрибутам, индексы, преобразования и форматирующие выражения не поддерживаются. Пустой, неизвестный или слишком длинный шаблон не проходит проверку.

## Применение

Локально:

```bash
.venv/bin/python -m scripts.validate_data
```

На сервере после редактирования файла:

```bash
cd /opt/alisa-schedule
docker compose run --rm --no-deps skill python -m scripts.validate_data
docker compose restart skill
```

Перезапускайте сервис только после успешной проверки. Пересборка образа для текстов не требуется: каталог `data` подключён к контейнеру. Другой путь задаётся переменной `RESPONSES_FILE`.

В текстах используйте привычные студенту слова. Один ответ должен решать один вопрос; справка вызывается командой «помощь». Не убирайте различие между «пар нет», «расписание не опубликовано» и «источник недоступен».
